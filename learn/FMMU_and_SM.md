EtherCAT 中 Sync Manager 与 FMMU 的协同工作机制
FMMU 与 Sync Manager（SM）是 EtherCAT 从站控制器（ESC）中硬件级联动的两大核心组件，二者分工明确、深度绑定，共同实现 EtherCAT 高实时、高可靠、高同步的数据通信。
一、核心定位与分工边界
二者的核心能力完全互补，共同构成了 EtherCAT 数据交换的硬件基础：
表格
组件	核心定位	核心职责	解决的核心问题
FMMU（现场总线内存管理单元）	硬件级地址翻译官 + 数据筛选器	主站全局 4GB 逻辑地址 ↔ ESC 本地物理地址的映射，支持字节 / 位级数据过滤与搬运，全程无 CPU 干预	解决 “总线数据该放 / 取自 ESC 哪个内存地址” 的路由问题，是 EtherCAT“一帧多从站、飞读飞写” 的核心支撑
Sync Manager（同步管理器）	缓冲区管家 + 同步门卫	管理专属物理内存缓冲区，实现 EtherCAT 侧（主站）与 PDI 侧（从站 MCU / 应用）的无冲突数据交换，处理缓冲区切换、握手、中断、错误检测、同步联动	解决 “数据怎么安全、同步、一致地在主站和从站应用之间交换” 的同步问题，是数据确定性与可靠性的核心保障
核心约束：FMMU 的所有映射目标地址，必须落在某个 SM 专属管理的物理缓冲区范围内，禁止映射到无 SM 管控的内存区域。
二、初始化阶段：配置绑定与协同前提
在 EtherCAT 从站 Pre-Operational 预运行阶段，主站会严格按照先配置 SM，再配置 FMMU的顺序完成初始化，完成二者的绑定，为运行时协同奠定基础：
SM 通道配置：主站为每个通信通道分配独立的 SM 通道（标准约定：SM0/SM1 为邮箱通信通道，SM2 为主站→从站 RxPDO 输出通道，SM3 为从站→主站 TxPDO 输入通道），配置缓冲区物理起始地址、长度、数据方向、工作模式（缓冲 / 邮箱）、中断、顺序模式、DC 同步联动等核心参数，划定 SM 专属管控的物理内存范围。
FMMU 映射配置：基于已配置的 SM 缓冲区参数，主站配置 FMMU 映射条目，将主站逻辑地址空间的对应段，精准映射到对应 SM 管理的物理内存区间，同时配置映射方向（读 / 写）、位宽，确保映射范围完全落在 SM 缓冲区地址内，无越界。
绑定关系：通常一个 FMMU 条目绑定一个 SM 通道；也支持多个 FMMU 映射同一个 SM 的不同位段（位级映射），实现多组数据共享同一个 SM 缓冲区。
三、运行时核心协同流程
1. 主站→从站下行数据交换（RxPDO 输出，典型为 SM2）
这是主站向从站发送控制指令的核心流程，二者协同完成数据的精准投递与安全交付：
主站发送逻辑寻址的 EtherCAT 数据帧，帧内携带全网络所有从站的输出过程数据，通过 “飞读飞写” 机制在总线中传输。
帧到达 ESC 后，FMMU 首先完成硬件级处理：匹配帧内逻辑地址与本地映射条目，过滤出属于本从站的输出数据，完成逻辑地址→物理地址的翻译，将数据写入对应 SM2 管理的缓冲区物理内存。
SM 接管并执行一致性管控：
完整性检测：通过缓冲区首字节 + 尾字节写入检测，或启用顺序模式时校验全字节的顺序写入，确认数据完整无丢帧；
缓冲区切换：若为 3 缓冲模式（DC 同步常用），将写入完成的后台缓冲区切换为就绪态，禁止 EtherCAT 侧再写入，同时给 PDI 侧开放读取权限，彻底避免主站与 MCU 同时读写的竞争；
事件触发：完成缓冲区接管后，按配置触发中断、喂狗信号，通知 PDI 侧数据就绪；
错误处理：若出现无效帧、写入不完整，按规则重置缓冲区，置位错误标志，避免无效数据被读取。
PDI 侧（从站 MCU）通过 SM 状态寄存器读取就绪缓冲区的有效数据，完成一次下行数据交换；若启用 PDI 写确认功能，读取完成后写入缓冲区最后一个字节，关闭缓冲区，通知 SM 可接收下一帧数据。
2. 从站→主站上行数据交换（TxPDO 输入，典型为 SM3）
这是从站向主站回传采集数据的核心流程，二者协同完成数据的同步采集与精准回传：
PDI 侧（从站 MCU）将采集的输入数据写入 SM3 管理的缓冲区，SM 检测到完整写入后，完成缓冲区切换 / 状态更新，标记数据为就绪态，锁定数据避免被中途修改。
主站发送逻辑寻址的读数据帧，遍历总线读取所有从站的输入过程数据。
帧到达 ESC 后，FMMU 硬件解析逻辑地址，匹配到 SM3 缓冲区的映射条目，从 SM 管理的就绪缓冲区中读取对应有效数据，实时填充到 EtherCAT 帧中，随帧转发回主站。
SM 检测到 FMMU 读取完成后，按配置触发中断，通知 PDI 侧可写入下一组输入数据，完成一次上行数据交换。
四、特殊场景的深度协同
1. 邮箱通信（非周期 SDO）的协同
邮箱通信用于 SDO 配置、参数读写等非周期数据交互，采用 SM0（主站→从站接收邮箱）+SM1（从站→主站发送邮箱）的握手模式：
主站发送 SDO 请求，通过 FMMU 映射写入 SM0 缓冲区，SM 检测到完整写入后触发中断，通知 MCU 读取请求；
MCU 处理完成后，将响应写入 SM1 缓冲区，SM 标记数据就绪；
主站发起读取时，FMMU 从 SM1 缓冲区读取响应数据，回传给主站。
此处 SM 负责邮箱的握手、流量控制、溢出检测，FMMU 负责地址映射，二者配合完成可靠的非周期数据通信。
2. 分布式时钟（DC）同步下的协同
DC 同步的核心是通过 SM 与 DC SyncSignal 的硬件联动，实现全网络纳秒级的同步数据交换，FMMU 则负责数据的提前搬运：
同步输出场景：主站提前通过 FMMU 将输出数据写入 SM 的后台缓冲区，DC 的 SyncSignal 到达预设同步时刻时，SM 原子性完成缓冲区切换，将新数据同步开放给 PDI 侧，实现全网络同步输出更新；同时 FMMU 可继续写入下一个周期的后台缓冲区，无冲突。
同步输入场景：DC 的 SyncSignal 触发全局同步输入采样，MCU 将锁存的同步时刻采样数据写入 SM 缓冲区，主站通过 FMMU 读取的是全局一致的同步采样数据，保证全网络输入的时间同步精度。
3. 大缓冲区数据一致性的协同保障
针对大于 3KB 的超大缓冲区（需多帧传输），SM 的顺序模式与 FMMU 的写入动作深度协同，避免中间帧丢失导致的数据不一致：
FMMU 按帧依次写入缓冲区数据，SM 启用顺序模式后，会校验 FMMU 是否从首字节开始，按顺序写入了缓冲区的所有字节；
只有当最后一个字节被写入，且所有前置字节均完成写入时，SM 才会接管缓冲区，标记数据就绪；
若中间帧丢失、写入不完整，SM 会直接重置缓冲区，要求从头重写，彻底避免无效数据被 PDI 侧读取。
五、核心协同逻辑总结
FMMU 与 SM 是 ESC 中不可分割的协作组合：
FMMU 是高速通信的基础，它让主站可以用单个逻辑帧访问全网所有从站，无需逐个节点寻址，把总线带宽利用率提升到 90% 以上；
SM 是可靠通信的核心，它解决了主站与从站应用的访问冲突，保障了数据一致性，同时实现了与 DC 同步的硬件联动，满足硬实时控制的需求。
二者一内一外，一个管地址路由，一个管同步管控，硬件级的协同实现了 EtherCAT 微秒级周期、纳秒级同步的工业实时通信能力。
